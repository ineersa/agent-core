A sound structure with a specific startup gap

The run engine, canonical event history, process ownership, and public extension seam fit together coherently. The evidence does not support a broad rewrite.

Extension loading is the clearest exception. Its interface promises failure isolation, but construction and some later lifecycle steps sit outside the guarded registration path.

The durable seam

session_id === run_id. Canonical events describe conversation and run history. Operational database rows support bounded coordination, not a second conversation archive.

RunMessageProcessor serializes transitions. RunCommit appends events before it updates operational state and dispatches effects.

Tool-batch snapshots, deferred batches, questions, and background-process records have distinct durable coordination roles. Not every database table can be rebuilt from events.

The extension and provider seams

Concrete extensions register through the public ExtensionApi contracts. Host adapters translate tools, hooks, jobs, and TUI operations into owning modules.

Symfony AI construction selects provider adapters. AgentCore coordinates model invocation; src/Platform contains provider protocol differences.

Two runtime adapters make AgentSessionClient a real seam. Provider variation and independently packaged extensions also justify their seams.

Operational risks and documentation drift

Known limitation

MCP cannot enforce each tool call's budget

McpConnectionManager::callTool() documents that the SDK exposes neither per-call timeout nor cancellation. Client-construction timeout is a different guarantee.

This is a real interface limit, not evidence that a particular call hung. Do not replace the SDK or add a custom transport on this review alone.

src/CodingAgent/Mcp/Client/McpConnectionManager.php:242–290

Documentation defect

The TUI lane requires a PHAR

The testing skill says TUI replay tests use source and do not require PHAR. Current Castor unconditionally calls phar_ensure(), including filtered TUI runs.

Both facts can be stated precisely. Behavioral TUI replay uses source; the lane also includes packaged-artifact boot proof. This review did not change the skill.

.castor/e2e.php:81–101
.agents/skills/testing/SKILL.md, PHAR-based testing

Documented degradation

Permanent run-control failure bypasses normal hooks

WorkerFailedEventSubscriber appends terminal failure outside normal RunCommit. Post-commit tool-batch cleanup can be bypassed; later lifecycle cleanup remains a separate recovery mechanism.

Keep the run-control ownership restriction and Doctrine reset ordering. No evidence here justifies a global failure subscriber.

src/CodingAgent/Runtime/Messenger/{WorkerFailedEventSubscriber,RunControlDoctrineFailureResetSubscriber}.php

Coupled upstream seam

Terminal replacements carry an upgrade obligation

Class aliases compensate for Symfony TUI's final concrete renderer and writer types. They are deliberate adapters, not ordinary interchangeable implementations.

Review these contracts on Symfony TUI upgrades. Keep the existing fail-closed installation and rendering proofs until normal injection can preserve behavior.

Refactors this review does not recommend

Tempting changeWhy it does not earn its cost
Merge parent and child pollersThe repeated cursor loop is small. Parent retries and degrades, replaces history, and restores editor state. Child replay hydrates a separate snapshot and applies different removal rules. A shared interface would expose those differences as configuration.
Unify live transitions and replayLive handlers decide admissibility and effects; replay interprets committed facts. Paired tool and compaction rules do not establish a defect. Keep replay independent of process-local execution and Messenger.
Move answers into ToolCallResultHandlerCommand-side answer validation is not result-side human-input suspension. That move would relocate complexity and create a second command router.
Split process client by class lengthIts implementation hides startup, readiness, restarts, per-run buffers, and process cleanup behind an existing small interface. That is depth. Splitting state ownership can reduce locality.
Merge session creation and recoveryNormal creation coordinates new metadata and exclusive directory creation. Recovery reads surviving canonical events after metadata loss and has different refusal and degradation rules.
Add more TUI composition interfacesThe current factory earns its role by creating fresh per-session state. Named projector lookup and repeated ChatScreen overlay surgery are local cleanup opportunities, not grounds for another public seam.
Treat RuntimeEventMapper as deepIt only forwards to RuntimeEventTranslator. The mapper's deletion test shows no lost behavior, but removing this naming facade is low leverage. The translator, not the forwarding facade, owns the real mapping implementation.
Split provider construction preemptivelyTagged builders already isolate real provider variation. Optional raw-capture lifecycle is a possible local cleanup, not a reason for a new provider framework.

Evidence, method, and limits

What was inspected

  • All four source roots, the public extension contracts, concrete extension packages, configuration wiring, Castor, release CI, and installer architecture.
  • Scoped JetBrains symbol, caller, and structure inspection plus targeted source reads.
  • Existing tests at the relevant seams, following the testing skill and tests/AGENTS.md. No tests were run.
  • The last 100 non-merge commits for change pressure. TUI and runtime dominated recent activity, but scope expanded to the full codebase at the user's direction.
  • Root and applicable nested instructions, depfile.yaml, session, TUI, and distribution documentation.

What this does not establish

  • No fresh Deptrac, static analysis, live provider, contention, performance, or terminal correctness result.
  • No exhaustive security audit or proof that every allowed dependency is desirable.
  • No complete trace of every Messenger handler, CLI command, auth path, or Codex WebSocket continuation.
  • No measured launch-resolution cost or observed mismatch between deferred intent and actual model.
  • No repository edits, task creation, implementation proposal with new signatures, or grilling session.
No root CONTEXT.md or tracked docs/adr/ was found. Domain names come from current code and project documentation. This report preserves documented decisions rather than treating the absence of ADRs as permission to reopen them.
