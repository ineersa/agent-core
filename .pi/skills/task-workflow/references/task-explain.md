# task-explain: Discuss Before Implementing

This phase is read-only: no status changes, task metadata, file edits, or implementation forks.

1. Read the task and referenced docs.
2. Scout only in proportion to uncertainty: none when context is sufficient, one for an unfamiliar bounded area, parallel only for genuinely independent high-risk lenses. Researchers are allowed for external information; batch independent scouts/researchers in one parallel call.
3. Present a structured plan: summary, affected areas, implementation steps, risks/open questions, and suggested validation.
4. Discuss decision points with the user; never resolve ambiguity silently.
5. Stop. The user runs `task-start` when ready.
