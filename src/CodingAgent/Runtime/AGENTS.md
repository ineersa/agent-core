# Runtime model

- `AgentSessionClient` is the TUI/runtime boundary.
- `Runtime/Contract` and `Runtime/Protocol` define command/event DTOs for session/runtime protocol surfaces.
- Controller owns workers and process lifecycle. `run_control` owns `RunState` and durable transitions. `RuntimeEventTranslator` consumes `RunEvent` (not `RunState`) to build protocol DTOs.
- Live committed events travel on controller stdout. Transient stream deltas use sequence `0` and stay out of durable replay.
- Application LLM retries emit transient `llm.request_retrying` (seq=`0`) for TUI working-status progress. Retry observer wiring is independent of `streamObserverEnabled`; compaction keeps stream deltas suppressed.
- TUI may depend on CodingAgent directly for ordinary service ownership; do not add Runtime/Contract catalog interfaces solely to isolate TUI from CodingAgent modules. Follow `depfile.yaml`.
- CodingAgent must not depend on TUI.
- `Runtime/InProcess` calls AgentCore directly; `Runtime/Process` uses headless JSONL subprocess.
- `src/CodingAgent/CLI/AgentCommand.php` wires TUI via `Ineersa\Tui\Application\InteractiveMode`.
- Canonical source: `.hatfield/sessions/<id>/events.jsonl` via `EventStoreInterface`. Overview: `docs/async-runtime-architecture.md`.

## Application maintenance commands

`AttachRun`, `SelectHistoryPrompt`, and `RepairSession` live in `CodingAgent\Application\Message`. Controllers and the in-process client submit them on `agent.command.bus` to `run_control`. `SessionMaintenanceHandler` owns their application policy and runtime replies. Sharing a transport with framework commands does not make them AgentCore concepts.

Attach completes pending-question cancellation and context refresh through `RunMessageProcessor` before returning, without starting a model turn. History selection and repair use `RunCommit` under the owner lock. The controller neither reconstructs execution state nor writes canonical history.

Subagent progress consumption uses application-owned `ConsumeSubagentProgressDTO` and `SubagentProgressCoordinationHandler`. The handler rereads the current lifecycle projection, advances the existing consumption marker, and dispatches the existing lifecycle delivery message. The descriptor captures its timestamp before commit; it carries no repository, closure, or execution state. Lifecycle redelivery remains a separate supported post-commit action. The pending journal now recovers these application-owned actions before publishing its committed cut. Repeated delivery remains idempotent coordination, not permission to rerun external work.

Prepared parent and child appends use `JsonlAppendJournal` beside their existing canonical archives. Its bounded manifest references exact staged JSONL bytes and a separate serialized work file. Readers stop at the predecessor offset until explicit owner finalization. Recovery compares bounded chunks, preserves allocated sequence holes, and rejects changed predecessor identity, mismatching suffixes, and extra tails. Finalization and append use the existing per-run storage lock.

`ExecutionPendingDeliverySubscriber` sweeps generic LLM, compaction, and standalone-shell operation rows on run_control worker start and idle ticks. Each callback reads at most 32 scalar references. Durable child reservations scope the root session and nested children without operational projection rows. Armed requests retain their original authorization stamp; ResultReady rows repeat the original owner notification. An unfinished transition blocks publication for that run. Query, storage, and transport failures are logged without deleting or dispositioning work.

Generic claims acquire a nonexpiring worker-instance Symfony Flock lock before entering Running. Recovery holds the same exclusive lock through result validation and the database decision. Live claims remain Running. A dead claim with a valid immutable result seal becomes ResultReady. Missing seals produce durable OutcomeUnknown evidence, never automatic re-execution. Corrupt or unreadable seals retain Running evidence, log local degradation, and advance the bounded page cursor so healthy Armed/ResultReady/unknown rows and cleanup in other owned runs continue. Later sweeps revisit the failed identity. `worker_pid` is diagnostic only; ownership is the worker-instance lock and claim receipt. The `ExecutionOperation` entity exists for ORM schema mapping of `execution_operation`; the store uses DBAL, not the entity API. Oversized gated requests are rejected by the existing 16 MiB encode bound before `RunCommit` appends or arms authorization.

OutcomeUnknown notices reach run_control through the same bounded sweep. A matching current invocation commits the existing failed-run event with a side-effect warning. Old-generation notices retire without changing current execution. Notice acknowledgement requires a verified pending transition. Unknown evidence blocks further automatic execution even after acknowledgement.

`ToolPendingDeliverySubscriber` visits one ordinary-tool snapshot on each run_control startup or idle callback. It resolves the owner and nested children through durable reservations, retaining scalar cursors between callbacks. Snapshot identity and filename are validated. Armed delivery requires the current stored invocation to match its authorization hash. ResultReady repeats the stored result. Pending transitions prevent publication. A delivery failure advances to the next run; the next sweep retries the unresolved snapshot.

Ordinary-tool claims retain a nonexpiring worker-instance exclusion lock and persist its key in Running evidence. The tool sweep holds exclusive dead-worker ownership while adopting a matching complete result snapshot, transferring verified deferred ownership, or recording OutcomeUnknown. Live claims remain Running. A mismatching orphan retains the original evidence and reports failure. An ordinary snapshot read never deletes unpublished evidence when its predecessor is unavailable.

Generic and ordinary claims share `RunLockManager` serialization with unknown decisions. Unknown receipts block new claims across both authorities. Ordinary unknown notices repeat until a verified owner transition acknowledges them. Acknowledgement does not erase possible side effects or authorize another attempt. Failed or blocked runs do not prevent the sweep from visiting reserved children.

Explicit `/repair` previews unknown receipts and their side-effect warning. Apply verifies worker exclusion and commits the warning before retiring receipts through replayable coordination. Old deliveries remain unauthorized. Active-operation repair uses the original frozen request or saved result. Missing authorization is refused rather than reconstructed.

Core control deliveries and application maintenance check durable accepted identities before history discard or handler preparation. Attach and selection capture fresh IDs at their producers. Attach accepts its root only after refresh and separately fences committed cancellation. Duplicate selection emits the existing transient `command.ack` with `status: accepted`, without another history-position event. Repair journals retirement and synthetic history fixes together. Its verified delivery action repeats original authorization references without arming new requests. Essential after-turn coordination is journaled and recovered before source acceptance.

Owner entry verifies an unfinished physical suffix and recovers supported coordination before normal replay. Unsupported actions remain hidden and block mutations, including permanent-failure append attempts. Mailbox finalization uses the captured command identities and FIFO cutoff, not a newly read drain. Source acceptance follows required coordination and precedes journal removal. Immutable request/result files and completed tool-result bodies are reclaimed only after durable Consumed/Stale disposition and finalized coordination, in bounded startup/idle pages. Live Armed/Running/ResultReady work, unresolved OutcomeUnknown, deferred ownership, human waits, and launch inputs needed for handoff are retained. Retired unknown receipts keep scalar fences only. Pending intent files remain until required coordination succeeds; operation rows and batch authority own redispatch without duplicate full-work copies. Missing authorization is not recreated after reclaim. Flush checks establish the tested process-failure boundary, not power-loss durability.
